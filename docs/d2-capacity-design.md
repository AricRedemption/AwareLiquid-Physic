## 2. 接口解剖(架构事实)

`LiquidOperatorHamiltonianModel`(field_eval.py,M2 配置):
liquid core(LTC,d_model=48)→ `infer_context` → **ctx ∈ R^8**
(context_dim=8)→ `OperatorPotential`(FNO,width=32,depth=4)逐块 FiLM
条件化。FiLM 是**通道仿射**:每块 `v ← scale(ctx)⊙v + bias(ctx)`,
scale/bias 各为 Linear(8→32),空间维广播。

关键结构事实:**ctx 对势能的全部影响被限制在每块 2×32=64 个标量的均匀
通道调制**;空间变化的 ctx 依赖(真任务恰恰需要:V(q|c)=Σᵢ cᵢ²/2·(Δq)²
的系数逐节点变化)只能靠"均匀 FiLM × 固定谱核"的深层组合间接合成。
真值的 ctx→V 映射是**乘性、空间结构化**的——与 FiLM 的加性均匀调制
**参数化不对齐**。这是容量假设的构造性动机。

对照:M1 的隐藏参数是标量 ω,V(q|ω) 的 ω 依赖是全空间均匀的——FiLM
的均匀调制恰好对齐,M1 尚且输给 concat;M2 的 c(x) 是空间场,不对齐
更严重。

## 3. 三个竞争假设

| 假设 | 内容 | 若真,可观测量 |
|---|---|---|
| H_headroom | 任务不需要逐轨迹辨识,static 已近最优 | oracle ctx 也打不过 static |
| H_cap | 瓶颈在接口表达力(FiLM 参数化不对齐) | 真信息经 FiLM 无增益,但经更强接口有 |
| H_infer | 瓶颈在推断质量(ctx 丢失系数) | oracle 大幅优于 inferred,且探针读不出系数 |

## 4. Oracle context 的精确构造

生成器(`gen_wave_1d_inhomogeneous`):c(x) = c_mean + c_var·Σ_{m=1..4}
a_m·sin(2πmx/N + φ_m),a_m~U(0, 0.5/m),φ_m~U(0, 2π),再 clamp_min(0.2·c_mean)。
由 sin 和角公式,场是 8 个线性系数 {a_m cosφ_m, a_m sinφ_m} 的叠加——
**族恰好 8 维线性,与 context_dim=8 同维**(信息论上无欠充足混淆)。

**Oracle ctx(固定、确定性、零学习)**:对每条轨迹的 c(x)(32 节点)做
正交投影,取归一化系数:

```
α_m = (2/N)·Σᵢ c(xᵢ)·sin(2πmi/N),  β_m = (2/N)·Σᵢ c(xᵢ)·cos(2πmi/N)
ctx_oracle = [α₁,β₁,α₂,β₂,α₃,β₃,α₄,β₄] / c_var
```

该投影在生成族上几乎必然单射(共 8 维恰好张成;clamp 罕见激活,如触发
仅引入轻微非线性,如实注记)。c_mean 项为全族共享常数、零信息,故意排除。
**Oracle 臂从头训练**(C 臂),不做 eval 时换 ctx——避免对已训练 FiLM 的
OOD 污染。

### 判定(按 §5 预注册表)

- **E1-c 成立:ρ_CB = 0.742 ≤ 0.8 且探针 0.014 < 0.5 → H_infer 主嫌疑**
  ——瓶颈在 liquid core 的**推断质量**,不在接口表达力,不在任务 headroom。
- **H_headroom 否证**:ρ_CA = 0.726 < 0.9——真系统辨识信息经 FiLM 接口
  可兑现 **27%** MSE 改善;"M2 无 headroom"关闭。
- **H_cap 降为非binding**:同接口同容量,给真信息即得 27% 增益——接口
  能传值;它不是当前瓶颈的第一约束。
- **M2 增益近零的解释链闭合**:static≈liquid 因为推断 ctx 里没有可用的
  系数信息(探针≈0),而不是任务不需要辨识(oracle 证明需要、接口也送得到)。
- 诚实注记:线性探针是可读出信息的**下界**;信息可能以非线性形式存在——
  该漏洞由 E3 的 MLP 探针收口。

### E3 预注册:推断侧容量阶梯(先于任何运行钉死)

- **动机**:E1 把瓶颈定位到推断侧,但"容量不足"与"训练目标不给梯度信号"

- **设计**:liquid 臂 d_model ∈ {96, 192}(48 基线复用 E1),3 seeds,
  semigroup 环,其余同 E1;新增 **MLP 探针**(2×64 非线性读出,关"非线性

- **判定(先钉死)**:
  - ① **正(容量机制)**——任一规模的探针 corr(线性或 MLP)≥ 0.5 且
    MSE 较 48 基线下降 ≥10%,两条件同规模同时成立 → 推断容量是瓶颈,
    登记规模-增益曲线,接口消融的重入口条件随之核验;

    <5% → 容量不敏感,主嫌疑转向**训练目标不产生系统辨识梯度信号**
    (与 D 系列"覆盖/目标函数"叙事合流),容量方向关闭,登记目标函数侧

## 12. E4 预注册:推断路径的优化可达性(2026-09-19,算力闸门 v2 模式)

### 12.1 判读新证据(零算力,既有产物分析,轮 54)

E1 终判 JSON 的 train_loss:**oracle 0.000372 < liquid 0.000483 ≈ static
0.000495**。单步目标存在 **25% 信息溢价**而 liquid 收不到——修正 §11 的
"目标不产生辨识梯度信号":**信号存在**(oracle 臂证明 k=8 单步目标足以
分辨知情/无知势能),失败在**推断路径的优化可达性**(liquid 收敛到与
static 相同的 loss 平台,未走到 25% 更优的解)。假设精化:

- **H_reach(优化不可达,主嫌疑)**:ctx 路径梯度(经 24 步前缀 LTC
  推断)在训练中被 head 的直接拟合路径淹没,系统收敛到 ctx≈无信息的
  平台解;
- **H_horizon(视距付账,降级为次要)**:与 train_loss 溢价矛盾——信息
  价值在 k=8 已兑现 25%,存在性不再需要长视距解释(视距仍可能调节幅度,
  留作 R2 扫描轴)。

### 12.2 E4a 梯度饥饿探针(本机合规:零训练、<10 min)

- 设计:新初始化 liquid 模型,1–3 个批 forward+backward(**无 optimizer
  step,不构成训练**),量测 ‖∂L/∂core 参数‖ / ‖∂L/∂head 参数‖ 与激活级
  ‖∂L/∂ctx‖;oracle ctx 注入为对照(信息可用时 head 侧梯度应增大)。
- 判读(先钉死):① 比值 <1e-2 → 饥饿机制确认,登记为修复方向的机械
  依据;② 比值 ≥0.1 → 梯度非饥饿,失败在更晚阶段(如 ctx 塌缩到常数),
  由 R1 的辅助损失判别;③ 中间如实记录。
