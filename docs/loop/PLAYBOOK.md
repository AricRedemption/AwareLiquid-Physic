## 坑清单(每条都真实付出过代价)

- **`torch.linspace(...).long()` 浮点舍入会越过终点**(轮 22):候选起点
  越过 `S−k_train−1` 导致训练目标索引越界。→ 任何 linspace 取整后必须
  `.clamp(max=合法上界)`;派生量先确认 `steps+1` 语义。
- **`gen_spring` 返回 `steps+1` 个时刻**(轮 22):S 的推导处处可能差一,
  配对比较前先 `S = tensor.shape[1]` 实取,不要用生成参数回推。
- **管道尾命令吞退出码**(轮 22;**轮 92 复发**;**09-20 治理会话三犯**):`pytest -q | tail -1 && 下一步` 中
  pytest 失败也会继续(退出码取自 tail)。→ 门禁链写 `pytest -q && ...`
  或单独跑 pytest 不接管道。(轮 92 复发代价:提交信息误写"全绿"而实际
  1 failed——状态钉死测试被合法清欠过期,fix-forward 修正;门禁一律
  单独跑、看退出码、再提交。09-20 三犯代价:AMM-019 首个提交带 1 个
  失败不变式+失实"全绿"信息已推送,fix-forward 修正——**设计会话同样
  受此坑约束**,门禁链显式退出码:`pytest > /tmp/t.txt 2>&1; EC=$?`。)
- **`no_grad` 杀死 symplectic rollout**(轮 2):哈密顿头 `dV_dq` 内部用
  autograd,eval 前向必须 `torch.enable_grad()` 包裹(参考
  `eval_rollout_mse`),输出再 detach。
- **测试 Namespace 与脚本 argparse 漂移**(轮 13/14/22 三次):给
  `run_one` 加每个新 flag 后,`tests/test_eval_ks_ladder.py` 的 `_args`
  必须同步(已有 keep-in-sync 注释);AttributeError 就是这个。
- **结果目录 `benchmarks/physics_out_v02` 是 gitignored**(轮 2 起):
  结果 JSON 只留本地 + audit,数字必须抄进 PRD 记录,路径仅作本地索引。
- **新产物用子目录隔离**(轮 2 起):绝不覆盖 canonical 产物
  (如第九波 `sample_efficiency_p11.json`);脚本若固定写文件名,用
  `--out_dir 子目录` 隔离。
- **screening 与判定分离**:1 seed 只做闸门/校准,结论必须 3 seeds +
  预注册判据;口径偏离(如用了 k100 而非 k1)必须如实注记(轮 13)。
- **配对基线要看 pool**:同 pool seed 才可逐 seed 配对;`max(sizes)` 不同
  ⇒ pool 不同 ⇒ 只能指示性对比(轮 14 教训)。
- **field_eval 单 seed 全流程 ~7 分钟**:全量拆轮必须预声明(轮 7)。
- **后台长命令**:run_in_background + TaskOutput 轮询;脚本内 `time` 计时
  校准时长(轮 8 起)。
- **策略热更新竞态**(轮 51-52,2026-09-19 夜):用户会在会话运行中途往
  PLAYBOOK/GOAL-PROMPT 提交新规(本夜算力闸门 v1→v2 两次热更);E3 两跑在
  v2 落地后启动,违规(如实入档轮 53,不改写轮 52 判定行)。→ 解法:每次
  心跳启动任何执行类工作前,先 `git log --oneline -3 docs/loop/PLAYBOOK.md
  docs/loop/GOAL-PROMPT.md` 复查规则新鲜度再动手。(出处:轮 51-52;适用
  条件:多会话同仓;验证状态:已验证——本夜三次热更全部命中。)
- **训练循环不传轨迹索引 → 前缀字节指纹查表**(轮 51):需要给模型注入
  每轨迹潜变量(oracle ctx)但 train_semigroup/prefix 只喂 gather 切片时,
  以 t_obs 前缀 `numpy().tobytes()` 为键建行号表,零侵入训练循环;表外
  轨迹回退语义默认值(常数场→零投影即正确 oracle)。(出处:轮 51
  `OracleOperatorWrapper`;适用条件:批 = 母张量精确 gather、轨迹不重复
  生成;验证状态:已验证——A/B 臂与 D2 逐位复现。)
- **1-seed 筛查两连中**(轮 51/52,被验证有效的做法):E1 筛查 ρ 0.730/
  0.719 → 终判 0.726/0.742 同判定;E3 冒烟双探针 ≈0 → 终判同。筛查闸门
  实践有效,保持。(出处:轮 51/52;验证状态:已验证,n=2。)
- **新基准脚本的结果 JSON 顶层必须有 `results` 键**(轮 55):audit_results
  的 schema 硬要求,探针类脚本裸写 summary/per_batch 会被 --check 拒
  (付过 1 cycle)。→ 载荷包一层 `"results": {...}`,args/meta 顶层照旧。
  (出处:轮 55 grad_starvation_probe;验证状态:已验证。)
- **`ctx.retain_grad()` 量激活级梯度**(轮 55):对非叶张量 ctx(推断头
  输出)先 retain_grad 再进 rollout,backward 后 ctx.grad 即 ∂L/∂ctx;
  oracle 对照用 `row.clone().requires_grad_(True)` 叶张量解耦推断图。
  (出处:轮 55 grad_starvation_probe;验证状态:已验证。)

- **经验蒸馏轮最小闭环(轮 61,被验证有效的做法)**:补池时先 grep
  档案既有 query 族(PRD §19 轮 45/60 清单 + scan 档案节标题),本轮
  选**零重叠族**;3 次检索(每族 1 次)即可收口 ≥1 条入库,全轮非算力
  <15 分钟。方向类条目**当轮**追加 GOALS 队尾(写清 done_condition 可
  验证判据),防"档案写了、循环忘了"——队列恢复非空,下轮 goal_check
  自动路由。(出处:轮 61;验证状态:已验证——D5-EXPOSURE 即按此产出。)

- **goal_check 空 check_cmd ⇒ 假阳性 ACHIEVED 误弹**(轮 62,实付 1
  cycle):路由器对队首目标跑 `subprocess.call(check_cmd, shell=True)`,
  入队时漏写 check_cmd ⇒ 空命令退出码 0 ⇒ 刚入队未干活的目标被判达成
  弹出吞掉。→ ① 防线已修:goal_check 空 check_cmd 按未达成路由;
  ② 入队模板必须带轻量验收锚(grep 式 check_cmd,如 `grep -q "锚"
  docs/PRD.md`);③ 误弹后恢复:目标回写队首,在提交信息注明"误弹恢复"。
  (出处:轮 61 入队/轮 62 发现;适用条件:一切经 goal_check 的入队;
  验证状态:已验证——修复后 NOT-Achieved 路由正确。)

- **入新目标前先查工具/产物覆盖面**(轮 63,被验证有效的做法):蒸馏轮
  想入方向类目标时,先 grep 现有 TOOLS 工具与 benchmarks/ 产物目录
  (如 d3_* 已有 tobs8/tobs24 对照),确认新目标是**增量**(连续图谱/
  新框架)而非重复;check_cmd 锚写目标 ID 特异串(如 "D6-INFO-BUDGET
  判读"),不写会过早命中的泛词。(出处:轮 62 假阳性教训的推广;
  验证状态:已验证——D6 入队前查得 fisher_j 闭式已存在,目标即改为
  "图谱+分解"增量定位。)

- **闭式工具的图谱化复用**(轮 64,被验证有效的做法):已有一维/单点
  判据的秒级闭式工具(如 fisher_j)不必重写——沿未扫过的轴(窗口长度)
  做网格扫描 + 与已知渐近律(t³)对照,即可把单点结论升级为图谱级判读
  (无平台判定 + CRB 换算),全轮零算力 <10 分钟。数字抄 PRD,JSON 留
  gitignored 目录。(出处:轮 64;验证状态:已验证——D6 即按此交付。)

- **修复候选的条件性登记法**(轮 65,被验证有效的做法):蒸馏轮发现
  的修复候选若依赖未回传的外部结果(R1/R2 云跑),**不入队**(会与
  等待中的主修复占位冲突、路由器空转)——在 GOALS 队列规则节写
  "X 条件性重入口"注记(触发条件 + 入口内容 + scan 档案指针),
  仿 E2 先例。主结果回传判读时按条件执行,不丢候选。
  (出处:轮 65;验证状态:已验证——R1b 即按此登记。)

- **"积分器可逆"≠"动量翻转回程一致"**(轮 66,机制发现型坑):评估
  依赖文档声明前先做 1 步往返冒烟。velocity-Verlet 映射对称性对任意
  H 成立,但回程一致性 ⇔ T 偶——`_energy_mlp` 学习的 T 天然非偶,
  docstring "exactly time-reversible for ANY T,V" 声明过强(已修订)。
  教训:**结构性质的成立条件要分解**(守恒/可逆各自前提),文档声明
  与实现要 diff。(出处:轮 66;验证状态:已验证——偶 T 对照 1.2e-7
  vs 非偶 T 4.6e-1。)

- **蒸馏条目 [坐标]/[行动] 分流标记**(轮 67,被验证有效的做法):
  经验蒸馏的入库条目强制标注 [坐标](解读用,不进队列)或 [行动]

  当成待办撑大队列,也防行动点被埋进档案。(出处:轮 67;验证状态:

- **判负后路由表预注册**(轮 68,被验证有效的做法):外部依赖结果
  (云跑/回传)的修复线,除预注册判负标准外,**连同"判负后走哪条路"

  (处方可叠加),消灭"全判负则无处可去"分支。(出处:轮 68;
  验证状态:已验证——R1/R1b/R1c 三路分流表即按此成文。)

- **同主题跨角度分夜扫描**(轮 70,被验证有效的做法):大主题(如
  liquid 基座)不一次扫完——轮 45 走 system-ID 角度,轮 70 走工程
  前沿角度,角度清单可跨夜接续(PRD §19 轮 45 query 清单存档可查)。

- **判读数字必须随附假设声明**(轮 71,被验证有效的做法):派生量
  (CRB、上界、比值)入档时把**假设条件写进同一句**(如"CRB 0.084
  在单位观测噪声下"),否则引用时会丢语义——轮 71 判得本仓数据无噪,
  σ=1 是保守假设而非事实;若当初只记数字,层 1 结论会被反向误读。
  出处轮 71;验证状态:已验证(PRD §19 轮 71 注记即按此成文)。

- **附带诊断字段也要扫**(轮 72,被验证有效的做法):结果 JSON 的
  附带诊断(resolution、energy_drift 等)主判据之外常藏未判读信号
  (轮 72 发现超分容量反向)——蒸馏/等待轮用 10 分钟遍历既有产物
  JSON 的全部键做"再判读",发现的信号按"弱信号如实注记、不下结论"
  入档,并标注复验条件(如"R2 回传时带上")。(出处:轮 72;
  验证状态:已验证——resolution 反向信号即此产出。)

- **入队 check_cmd 用双锚**(轮 73,被验证有效的做法):轮 62 的单
  grep 锚防住了"空命令假阳性",但仍有残余假阳性面——判读锚字先写
  进 PRD、产物却烂尾时,单 grep 锚会误判达成。→ 带产物的目标入队
  用双锚:`grep -q "<判读锚>" docs/PRD.md && test -f <产物文件>`;
  判读锚只在判读写完时存在,产物锚只在文件落地时存在,**两个独立
  事件同时发生才算达成**。(出处:轮 73;适用条件:一切带文件产物
  的目标入队;验证状态:已验证——DH-DESIGN 入队时双锚均未命中,
  goal_check 正确路由 NOT-Achieved→迭代。)

- **kick 括号里的免费符号翻转**(轮 74,坑):给速度-Verlet 的 kick
  加新力项时,力以 **+dt/2·F** 进入(ṗ=−∇qH+F);写成
  `-0.5*dt*(dV + F)` 即静默反号成反阻尼——首跑探针抓到每步 ΔH
  严格为正、随 dt 线性。→ ① 任何新力项**先写单调/守恒探针再接线**
  (判据先行防不了实现错,防的是"接错线无感知");② 探针阈值用
  **对照臂归因**(γ≈0 对照臂 H_end/H0=1.000 vs 阻尼臂 <0.7),
  不拍固定魔数——本轮 1e-4 与 1e-3·H0 两版魔数都被实测打回后重标定。
  (出处:轮 74;适用条件:一切向辛积分器加力/项的改动;验证状态:
  已验证——反号 bug 首跑即捕获,修复后 95 测试全绿。)

- **机制命名四问对账模板**(轮 78,被验证有效的做法):给自有缺口
  找文献命名(如 E1 缺口→谱偏置)时,文档按四问组织——① 机制方向
  与证据方向一致吗(**含适用范围核查**:本轮对账发现 M1 的 ctx=ω
  只是幅值缩放、无频域差异轴,命名当场收窄到 M2 场线——范围收窄
  不是判负,不写范围才是坑);② 排除性证据兼容吗(E3/E4a/D6 逐层
  对账成表);③ 与既有命名分工明确吗(Gradient Starvation=竞争轴
  vs 谱偏置=频序轴);④ 可证伪预言预注册了吗(R1d 逐模式扫描,
  判负=平坦)。四问答不满的命名不配进 N1 正文。(出处:轮 78;
  适用条件:一切"缺口→文献命名"型判读轮;验证状态:已验证——
  四问模板当轮产出范围限定与可证伪预言,防了一次过度声明。)

- **评估口径透镜法**(轮 79 预注册,轮 80 执行收口,已验证):
  把领域标准指标(如混沌文献的 VPT)当**透镜**套到自家既有产物上
  做再判读,而不是重跑实验——三要素:① 先决可行性门(判负①:
  产物数据形状不支持即降级协议登记,本轮实测全库仅 d1b 有三点
  per-k);② 预设诚实出口(判负②:透镜无区分度就记"无区分度",
  本轮 θ=0.1 下两线档位分离但 prefix_n32 k10=0.0983 贴阈,定性
  分离只在 θ∈[0.1,0.16) 窄窗成立——**结论降格为呈现口径,
  不构成新判定**);③ 假设随附(θ 无自然归一化,引用必带)。
  这是轮 72"附带诊断字段也要扫"的推广:再判读透镜不止来自自家
  被忽略字段,也来自领域标准口径。(出处:轮 79/80;适用条件:
  蒸馏轮发现评估口径差时的零算力补齐;验证状态:已验证——
  透镜跑通且两次诚实降格机制都被用到。)

- **跨界基线公平性三声明模板**(轮 82,被验证有效的做法):登记
  类别跨界基线(如零样本 TSFM on 物理状态序列)时,协议文档必须
  含三声明并与数字同表出现——① 数据体制差异(预训练广度 vs 小样本
  结构化);② 非公平基线定位(类别跨界参考,非同台排名);③ 预期
  用途(读者参照:任一结果都有信息量,均不构成排名结论)。缺声明
  的跨界对比会被评审当稻草人打,有了声明则双向免疫(输了不伤、
  赢了不吹)。预期行为只可"预注册,非预言",判定以实测为准。
  (出处:轮 82 tsfm-baseline-protocol;适用条件:一切跨类别基线
  协议;验证状态:已验证——协议一次过判负标准①②。)

- **审计工具必查产物代际**(轮 84,坑+做法):审计某工具的实证语义
  时,必须同时查其产物 JSON 的 `args`(训练步数/规模)——本轮唯一
  probabilistic 产物是 train_steps=5 的语法冒烟(spread=1.2e-4≈0,
  logvar≈先验),若当实跑证据引用会把"模型塌缩到无不确定性"误读
  成实测量。→ ① 引用产物数字前先核 args 代际(冒烟/实跑/隐藏);
  ② 冒烟产物引用必须注明"仅验语法与数据形状";③ 工具有方差语义
  ≠ 有实跑方差数字——两回事。(出处:轮 84;适用条件:一切工具
  语义审计与产物引用;验证状态:已验证——冒烟代际被当场识别,
  N1 表述等级据此限定 L2。)

- **GOALS 入队编辑的孤儿围栏**(轮 83/85 两踩,坑):手工替换
  ` ```yaml\ngoal_queue: [] ` 块时若 old_string 不含闭合围栏,
